# 入局牌数可配置

**日期：** 2026-08-29  
**状态：** 已确认  
**范围：** 开房时选定每人每轮起始牌数；发牌与轮结兑钱都读这个数。  
**形态：** 微信小程序（现有麻将局记）

## 1. 目标与非目标

### 目标

- 开房人在首页「快速开局」（以及仍在用的创建页）能改入局牌数。
- 默认 **20**，按 **5** 加减，范围 **10–50**。
- 该数字写入这一局，整局（含后续轮次）都用它。开房后不可改。
- 每轮选庄确认后，四人都发这个数。
- 兑钱：`(当前牌数 − 入局牌数) × 底分`。破产仍是牌数到 0。
- 没有该字段的老局一律当 20。

### 非目标

- 不在选庄或对局中改牌数。
- 不按人设不同起始牌。
- 不做本机「上次用过的牌数」记忆。
- 不改番型、庄倍、杠分、房间码、占座。

## 2. 界面

### 2.1 首页「快速开局」

同一井里上下两行：

1. **底分** — 现有 1–5 档，不变。
2. **入局牌数** — 左 `−`、中当前数字、右 `+`。默认 20。到 10 时 `−` 变淡且不可点；到 50 时 `+` 同样处理。

副文案改为：「设好底分和牌数，邀请牌友用房间码入座」。

步进器做成大热区（与底分档同高量级），墨线圆钮，数字居中加粗。

### 2.2 创建页 `pages/create`

底分下方同样一行步进。逻辑与首页共用。

### 2.3 最近牌局 / 全部牌局

进行中副文案：`底分 {{chipValueYuan}} · {{startingChips}}牌`。  
已结束仍是 `已结束`。

### 2.4 流水页

`面值 {{chipValueYuan}} 元/牌 · 入局 {{startingChips}}`。

战场不另写一行。

## 3. 数据

字段名：`startingChips`（整数）。

写在 `sessions` 文档上，与 `chipValueYuan` 同级。开房时写入，之后只读。

校验（开房与云函数）：

- 整数
- `10 ≤ n ≤ 50`
- `n % 5 === 0`

缺字段或读到非法值：按 **20** 处理（兼容老局）。开房时若调用方传了非法值：拒绝创建。

`SessionSummary` / `listMySessions` 带上 `startingChips`（老局归一成 20）。

## 4. 领域

- `startCycle`：每人 `chips = startingChips`，`hasHu = false`。
- `settleCycle(seats, chipValueYuan, startingChips)`：`chipDelta = chips - startingChips`。第三参默认 20，避免旧调用崩。
- 小程序与 `sessionWrite` 各有一份相同规则（与现有 `settleCycle` 双份一致）。

## 5. 测试

- 步进：20→25、20→15；10 不再减、50 不再加；非法值归一 20。
- 结算：起始 10、当前 15、底分 2 → `chipDelta 5`、`yuan 10`。
- 开房 15 → 选庄后四人各 15；轮结按 15 算；下一轮仍发 15。
- 缺字段的文档当 20。
- 最近牌局进行中文案含牌数；流水页 meta 含「入局」。

## 6. 部署

改了 `sessionWrite`，需在开发者工具重新上传该云函数后，真机 / 开发者工具才生效。mock 单测不依赖云。
